  <name>Task 1: Add catalog cross-reference and Download column to recommendations table</name>
  <files>inference_proxy/static/js/node_detail.js</files>
  <action>
  Modify loadRecommendations() to fetch catalog and downloads alongside recommendations, then render a Download column. All changes are in this one function plus two new helper functions.

  1. PARALLEL FETCH with graceful degradation (per D-01, Pitfall 1):
     Inside loadRecommendations(), after the existing recommendations fetch succeeds, fetch catalog and downloads in parallel. Do NOT use Promise.all for these two -- fetch them individually and catch failures so catalog/download errors never block the table. Build two data structures:
     - catalogSet: a Set of repo_id strings from GET /admin/models/catalog response.models
     - downloadMap: an object keyed by repo_id from GET /admin/models/downloads array
     If either fetch fails, default to empty Set / empty object respectively. The table still renders with all Download buttons (graceful degradation).

  2. TABLE HEADER (per D-07):
     Add "<th>Download</th>" as the 7th column in the thead html string (after Memory).

  3. DOWNLOAD CELL RENDERING:
     The existing table is built via innerHTML concatenation. For the Download column, this won't work because buttons need addEventListener. Change the table-building approach: keep the innerHTML for columns 1-6 (Model through Memory), but after setting table.innerHTML, iterate the tbody rows and append a 7th td to each row using createElement. For each row at index i, corresponding to data.models[i]:

     Create a helper function renderDownloadCell(td, modelName, catalogSet, downloadMap) that populates a td element based on state priority (per RESEARCH operator precedence):
     a. If downloadMap[modelName] exists and status === "downloading": render a span with class "badge badge-in-progress", text "Downloading..."
     b. Else if downloadMap[modelName] exists and status === "complete", OR catalogSet.has(modelName): render a span with class "badge badge-complete", text "Downloaded" (DASH-02)
     c. Else if downloadMap[modelName] exists and status === "failed": render a button with class "badge badge-failed", style cursor:pointer, text "Failed -- Retry", addEventListener click calling triggerDownload(modelName, td) (DASH-01 retry)
     d. Else (default): render a button with class "btn-setup", text "Download", addEventListener click calling triggerDownload(modelName, td) (DASH-01)

     Set td.dataset.repoId = modelName on every download cell for poll-based lookup later.

  4. ROW ITERATION after innerHTML:
     After content.appendChild(table), select all tbody tr elements within the table. For each row at index i, create a td, call renderDownloadCell with data.models[i].name, catalogSet, downloadMap, then append the td to the row. Also add a th to the thead row for the Download header (alternatively, include it in the html string -- either approach works, just be consistent).

  Keep renderDownloadCell as a standalone function at module scope (outside loadRecommendations) since it will be reused by the poll updater in Task 2.

<task type="auto">
  <name>Task 2: Add download trigger and status polling</name>
  <files>inference_proxy/static/js/node_detail.js</files>
  <action>
  Add the download trigger function and the lazy polling mechanism. Two new functions at module scope, plus one module-level variable.

  1. MODULE-LEVEL STATE:
     Add var downloadPollTimer = null; near the top of the file (after ACTION_CONFIG or similar).

  2. triggerDownload(repoId, td) FUNCTION (per D-05, Pitfall 2, Pitfall 5):
     Async function that:
     a. Immediately updates the cell to "Downloading..." state: clear td, create span with class "badge badge-in-progress", text "Downloading...", append to td. This prevents flicker (Pitfall 2).
     b. POST to /admin/models/download with body { repo_id: repoId }, Content-Type application/json.
     c. If response.ok (accept both 200 and 202 per Pitfall 5): call showToast("Download started for " + repoId, "success") and call startDownloadPolling().
     d. If not ok: parse error body, call showToast with error detail, and re-render the cell as a retry button using renderDownloadCell(td, repoId, new Set(), { [repoId]: { status: "failed" } }).
     e. On catch (network error): showToast network error, re-render cell as Download button via renderDownloadCell(td, repoId, new Set(), {}).

  3. startDownloadPolling() FUNCTION (per D-03, D-04, Pitfall 4):
     Guard: if (downloadPollTimer) return; -- prevents multiple timers (Pitfall 4).
     Set downloadPollTimer = setInterval(pollDownloadStatuses, 4000);
     Also call pollDownloadStatuses() once immediately so the first update doesn't wait 4 seconds.

  4. pollDownloadStatuses() FUNCTION (per D-03, Pitfall 3):
     Async function that:
     a. Fetches GET /admin/models/downloads. On failure, return silently (don't break the poll loop).
     b. Builds a downloadMap object from the response array, keyed by repo_id.
     c. Selects all td[data-repo-id] cells in the document.
     d. For each cell: look up downloadMap[cell.dataset.repoId]. If found, call renderDownloadCell(td, repoId, catalogSetCache, downloadMap) where catalogSetCache is a module-level Set. If the download status is "complete", also add the repo_id to catalogSetCache so subsequent renders show "Downloaded".
     e. After updating all cells: check if any download in the response array has status === "downloading". If none: clearInterval(downloadPollTimer); downloadPollTimer = null; -- stop polling.

  5. CATALOG SET CACHE:
     Add var catalogSetCache = new Set(); at module scope. In loadRecommendations(), after building catalogSet, assign catalogSetCache = catalogSet; so the poll updater can reference it. This avoids re-fetching catalog on every poll tick.

  6. EDGE CASE -- RELOAD (Pitfall 3):
     loadRecommendations() already fetches downloads (from Task 1). The downloadMap built there handles the case where a user clicks Reload after a download completes -- the "complete" status from /admin/models/downloads will render as "Downloaded" even if catalog hasn't refreshed yet.
  </action>
