# Requirements Archive: v1.0 MVP

**Archived:** 2026-06-25
**Status:** All 19 v1 requirements implemented and tested

## v1 Requirements — All Complete

### Request Proxying

- [x] **PROXY-01**: Client can send chat completion requests via `/v1/chat/completions` and receive responses from a vLLM node — Phase 3
- [x] **PROXY-02**: Client can send text completion requests via `/v1/completions` and receive responses from a vLLM node — Phase 3
- [x] **PROXY-03**: Client can list available models via `/v1/models` with model name, node count, and availability — Phase 3
- [x] **PROXY-04**: Client can check gateway health via `/health` endpoint — Phase 3
- [x] **PROXY-05**: Gateway returns OpenAI-compatible error responses with proper status codes and error schema — Phase 3

### Streaming

- [x] **STRM-01**: Client receives streaming token-by-token responses via SSE for chat completions — Phase 3
- [x] **STRM-02**: Client receives streaming token-by-token responses via SSE for text completions — Phase 3
- [x] **STRM-03**: Gateway correctly forwards SSE `data: [DONE]` termination signal from vLLM — Phase 3

### Service Discovery

- [x] **DISC-01**: Gateway discovers vLLM nodes registered in etcd under a configurable key prefix — Phase 2
- [x] **DISC-02**: Gateway watches etcd for real-time node additions and removals without restart — Phase 2
- [x] **DISC-03**: Gateway routes requests only to nodes hosting the requested model (model-aware filtering) — Phase 4
- [x] **DISC-04**: Admin can view registered nodes, their models, and health status via admin API endpoint — Phase 6

### Load Balancing

- [x] **LBAL-01**: Gateway routes requests to the node with the fewest active connections (least-connections) — Phase 4
- [x] **LBAL-02**: Gateway drains active connections before removing a departing node from the routing pool — Phase 4

### Resilience

- [x] **RESL-01**: Gateway performs periodic health checks against vLLM nodes and marks unhealthy nodes as unavailable — Phase 5
- [x] **RESL-02**: Gateway retries failed pre-stream requests on another healthy node (does not retry mid-stream) — Phase 5
- [x] **RESL-03**: Gateway applies per-node circuit breaker that opens after consecutive failures and closes after recovery — Phase 5
- [x] **RESL-04**: Gateway shuts down gracefully, draining in-flight requests before stopping — Phase 5

### Observability

- [x] **OBSV-01**: Gateway emits structured JSON logs (structlog) for all requests with method, path, status, duration, and target node — Phase 6
