    Create inference_proxy/static/js/chat.js with the following capabilities. Use the DOMContentLoaded init pattern from dashboard.js.

    SHARED UTILITY -- showToast(message, type): duplicate the ~12-line function from dashboard.js (lines 3-14). It is small enough that a shared file is not warranted per D-09.

    STATE -- maintain a messages array (objects with role and content fields). This is the conversation history sent with each request per D-06. No localStorage persistence needed (session-only per REQUIREMENTS.md out-of-scope).

    MODEL SELECTOR (D-05, D-07, CHAT-03): on DOMContentLoaded, fetch GET /v1/models. Populate the model-select dropdown with option elements where value and text are each model's id field from the response data array. If the data array is empty or the fetch fails, set the select to a single disabled option "No models available" and disable send-btn per D-07.

    MESSAGE DISPLAY (D-01): function addMessage(role, content) that creates a div with class "message-bubble" plus "bubble-user" or "bubble-assistant". User bubbles: set textContent (not innerHTML -- user text is plain text). Assistant bubbles: set innerHTML to marked.parse(content) for markdown rendering per D-04. Append to message-area. Hide the empty-state element on first message. Return the bubble element for streaming updates.

    INPUT HANDLING (CHAT-01, UI-SPEC interaction contract): Enter key on chat-input calls sendMessage(). Shift+Enter inserts newline (per UI-SPEC accessibility). send-btn click also calls sendMessage(). After send, focus returns to chat-input.

    SEND MESSAGE (CHAT-01, D-08): function sendMessage() that reads chat-input value (trim, ignore empty). Add user message to messages array and display via addMessage("user", text). Clear chat-input. Disable send-btn and chat-input per D-08. Create an empty assistant bubble via addMessage("assistant", ""). Call streamResponse() passing the bubble element.

    SSE STREAMING (CHAT-02, D-08, D-11): async function streamResponse(bubble) that POSTs to /v1/chat/completions with JSON body containing model (from model-select value), messages (the full array), and stream:true. Use fetch + response.body.getReader() + TextDecoder per D-11.

    Parse the readable stream: buffer incomplete lines, split on newline, process lines starting with "data: ". If data is "[DONE]", finalize. Otherwise JSON.parse the chunk and extract choices[0].delta.content. Accumulate content tokens in a rawText variable. Per RESEARCH.md anti-pattern guidance, append raw text and render markdown at intervals: update bubble innerHTML with marked.parse(rawText) on each token (acceptable perf for typical response lengths per assumption A3).

    During streaming, append a span with class "streaming-cursor" containing "|" to the bubble after the markdown content. Remove it on stream complete.

    On stream complete: add the full assistant message to the messages array (role "assistant", content rawText). Re-enable send-btn and chat-input. Remove streaming cursor.

    ERROR HANDLING (D-09): if the SSE stream contains an error event (JSON with error.message field), display the error message inside the assistant bubble with class bubble-error. If fetch itself fails (network error), call showToast with "Could not reach the server. Check your connection." and type "error". In both cases re-enable send-btn and chat-input.

    SMART AUTO-SCROLL (D-10): before each content append during streaming, check isNearBottom(messageArea, 40). If true, after append, set messageArea.scrollTop = messageArea.scrollHeight. This pauses auto-scroll when user scrolls up and resumes when they scroll back to bottom.

    isNearBottom helper: return (el.scrollHeight - el.scrollTop - el.clientHeight) less than threshold.

    TEXTAREA AUTO-GROW: on input event of chat-input, reset height to "auto" then set height to scrollHeight + "px", capped at max-height 200px from CSS.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser to /v1/chat/completions | User-typed messages sent as POST body to proxy |
| Proxy to vLLM backend | Proxy forwards to backend, streams response back |
| marked.js rendering | Assistant response HTML rendered via innerHTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-03 | Tampering | marked.parse() innerHTML | accept | Assistant content from own vLLM backends only. User messages rendered as textContent (not innerHTML). Internal network tool -- XSS risk negligible. Add DOMPurify if tool becomes external-facing |
| T-19-04 | Denial of Service | Unbounded conversation history | accept | Session-only, user refreshes to clear. vLLM will return 400 if context window exceeded. Document as known limitation |
| T-19-05 | Information Disclosure | Conversation in JS memory | accept | No persistence, cleared on page refresh. Internal network only |
| T-19-SC | Tampering | CDN-loaded marked.js | accept | marked.js loaded from cdn.jsdelivr.net. Internal tool, low-value target. Pin to major version (@18) for stability |
</threat_model>
