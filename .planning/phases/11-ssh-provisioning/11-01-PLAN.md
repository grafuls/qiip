<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Gateway -> Remote Host (SSH) | Gateway initiates SSH connection to lab server; remote host is semi-trusted (internal network, shared key) |
| Gateway -> etcd (HTTP) | Gateway writes node registration data to etcd via HTTP gateway |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-01 | Spoofing | SSH known_hosts=None | accept | D-03: lab servers reimaged frequently, internal network only. Accepted risk. |
| T-11-02 | Tampering | Hostname in shell commands | mitigate | Validate hostname format before passing to asyncssh.connect — hostname is used as a network address by asyncssh, not interpolated into shell strings. Shell commands (setup.sh path) are hardcoded in provisioner, not derived from hostname. |
| T-11-03 | Information Disclosure | SSH key path logged | mitigate | Never log the key_path value. structlog fields log host, command, exit_status only. |
| T-11-04 | Tampering | Remote stdout injection | mitigate | Step marker parsing uses strict regex re.compile(r"\[STEP:(\w+):(START|OK|FAIL)\]"). Non-marker lines are only logged, never evaluated. |
| T-11-SC | Tampering | asyncssh install | mitigate | Package legitimacy audit passed: 12yr old, 18.4M/month downloads, slopcheck OK. |
</threat_model>
