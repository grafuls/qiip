# Phase 8 — UI Design Contract

> Visual and interaction contract for the operations dashboard. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (not a React/SPA project) |
| Preset | not applicable |
| Component library | none — semantic HTML + Simple.css classless framework |
| Icon library | none — text labels and color badges only |
| Font | System font stack via Simple.css `--sans-font` (`-apple-system, BlinkMacSystemFont, "Avenir Next", Avenir, "Nimbus Sans L", Roboto, "Noto Sans", "Segoe UI", Arial, Helvetica, sans-serif`) |

**CDN:** `<link rel="stylesheet" href="https://cdn.simplecss.org/simple.css">`

**Override CSS:** A single small `dashboard.css` file for badge styles only. Loaded after Simple.css.

---

## Spacing Scale

Simple.css handles spacing via its own defaults on semantic HTML elements (headings, tables, paragraphs). No custom spacing tokens are needed for this phase.

Declared values for the custom `dashboard.css` overrides only:

| Token | Value | Usage |
|-------|-------|-------|
| badge-px | 8px | Horizontal padding inside status badges |
| badge-py | 4px | Vertical padding inside status badges |
| table-cell-px | 8px | Extra horizontal padding on `<td>` if Simple.css default feels tight |

Exceptions: none — all other spacing is Simple.css defaults on semantic HTML.

---

## Typography

Simple.css controls all typography. No custom font sizes or weights are declared. The framework uses the system sans-serif stack with responsive defaults.

Two weights only: 400 (body/table text) and 600 (all emphasis — badges, headings, table headers).

For reference, the effective values Simple.css applies (with h1 weight overridden to 600 in `dashboard.css`):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (1rem) | 400 (normal) | 1.5 |
| Label / Badge | 14px (0.875rem) | 600 (semibold) | 1.0 |
| Heading (h1) | 2rem (32px) | 600 (semibold) | 1.2 |
| Table header (th) | 16px (1rem) | 600 (semibold) | 1.5 |

The only custom typography is the badge `<span>` text at 14px / 600 weight and the h1 weight override to 600, both defined in `dashboard.css`.

## Color

Simple.css provides light/dark mode automatically via `prefers-color-scheme`. All base colors come from the framework.

### Simple.css Base Colors (DO NOT override)

| Role | Light Value | Dark Value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) `--bg` | `#fff` | `#212121` | Page background |
| Secondary (30%) `--accent-bg` | `#f5f7ff` | `#2b2b2b` | Table header, alternating rows (if used) |
| Text `--text` | `#212121` | `#dcdcdc` | Body text |
| Text light `--text-light` | `#585858` | `#ababab` | Secondary text |
| Accent `--accent` | `#0d47a1` | `#ffb300` | Links only |

### Custom Badge Colors (defined in `dashboard.css`)

These are the ONLY custom colors in this phase. Each is used exclusively for status badges.

| Badge | Background | Text | Used For |
|-------|-----------|------|----------|
| Healthy / Closed | `#16a34a` (green-600) | `#fff` | Node status "healthy", circuit breaker "closed" |
| Unhealthy / Open | `#dc2626` (red-600) | `#fff` | Node status "unhealthy", circuit breaker "open" |
| Draining / Half-open | `#ca8a04` (yellow-600) | `#fff` | Node status "draining", circuit breaker "half_open" |

Accent reserved for: links only (Simple.css default behavior). Badge colors are separate from the accent system.

## Component Inventory

No component library. All UI is semantic HTML elements styled by Simple.css, plus badge `<span>` elements.

| Element | HTML | Custom CSS | Notes |
|---------|------|------------|-------|
| Page container | `<body>` inside `<html>` | none | Simple.css centers and constrains width |
| Page title | `<h1>` | yes (weight override to 600) | "Node Fleet Dashboard" |
| Node count summary | `<p>` | none | "{N} nodes registered" — shows total count |
| Node table | `<table>` | none | Simple.css styles tables automatically |
| Table header | `<thead><tr><th>` | none | 6 columns matching AdminNodeResponse fields |
| Table rows | `<tbody><tr><td>` | none | One row per node, populated by JS fetch |
| Status badge | `<span class="badge badge-{status}">` | yes | Pill-shaped colored badge (see Badge CSS below) |
| CB state badge | `<span class="badge badge-{state}">` | yes | Same badge styles, maps to circuit breaker states |
| Loading state | `<p>` inside `<tbody>` | none | Shown while JS fetches data |
| Error state | `<p>` | none | Shown if fetch fails |

## Interaction Contract

| Interaction | Behavior |
|-------------|----------|
| Page load | Render HTML shell with empty `<tbody>`, JS fetches `GET /admin/nodes`, populates table |
| Fetch success | Replace loading indicator with table rows |
| Fetch error | Show error message in table body area |
| No nodes | Show empty state message in table body area |
| Click/navigation | None — read-only dashboard, no interactive elements |
| Auto-refresh | NOT in this phase (Phase 9) |

## Data Flow

```
Page Load:
  Browser GET /dashboard
    -> FastAPI renders Jinja2 template (HTML shell + empty table)
    -> Browser receives HTML, loads Simple.css from CDN, loads dashboard.css
    -> JS runs: fetch("/admin/nodes")
    -> On success: populate <tbody> with one <tr> per node
    -> On error: show error message in <tbody>
```

The `/admin/nodes` endpoint already exists (Phase 7). No new API endpoints needed.

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Semantic HTML | Use `<table>`, `<thead>`, `<tbody>`, `<th scope="col">` — screen readers parse tables natively |
| Color + text | Badges show status text inside the colored pill — never color-only |
| Dark mode | Simple.css handles automatically via `prefers-color-scheme: dark` |
| Keyboard nav | Not applicable — no interactive elements |
| Badge contrast | White text on green-600/red-600/yellow-600 meets WCAG AA for large text (14px semibold) |
