## QUADS Status Indicator

Displayed in `.header-right` alongside existing `#last-updated` and `#poll-warning` elements (D-09).

### Status States

| Status | Condition | Badge Class | Label |
|--------|-----------|-------------|-------|
| Connected | `consecutive_failures == 0` AND `last_sync != null` | `.badge-healthy` | `QUADS: connected -- {relative_time} ago` |
| Stale | `consecutive_failures >= 1` AND `consecutive_failures < 3` | `.badge-draining` | `QUADS: stale -- last sync {relative_time} ago` |
| Unavailable | `consecutive_failures >= 3` OR `last_sync == null` | `.badge-unhealthy` | `QUADS: unavailable` |

The relative time is computed client-side from `last_sync` ISO timestamp. Format: "2m ago", "15m ago", "1h ago".

### Backend Data Source

Expose QUADS staleness on the existing `GET /admin/nodes` response is not ideal (it is per-node data vs system-level metadata). Recommend a lightweight `GET /admin/quads/status` endpoint returning:

```json
{
  "status": "connected",
  "last_sync": "2026-07-17T10:30:00Z",
  "consecutive_failures": 0
}
```

Add this fetch to the existing `Promise.all` in `refreshDashboard()`.

Source: D-09, D-10 from CONTEXT.md. QUADSPoller properties from `quads/poller.py`.

## Interaction Contracts

### Action Button Wiring

| Action | HTTP Method | Endpoint | Body | On Success |
|--------|-------------|----------|------|------------|
| Setup (inline) | POST | `/admin/nodes/setup` | `{ "hostname": node.node_id }` | Toast "Setup started for {node_id}" |
| Setup (manual) | POST | `/admin/nodes/setup` | `{ "hostname": input.value }` | Toast + clear input |
| Teardown | DELETE | `/admin/nodes/{node_id}` | none | Toast "Teardown started for {node_id}" |
| Retry | POST | `/admin/nodes/setup` | `{ "hostname": node.node_id }` | Toast "Retry started for {node_id}" |
| Cancel | DELETE | `/admin/nodes/{node_id}` | none | Toast "Cancelled provisioning for {node_id}" |
| Force Teardown | DELETE | `/admin/nodes/{node_id}` | none | Toast "Teardown started for {node_id}" |

All action buttons disable on click to prevent double-submission. `refreshDashboard()` will restore button state on next poll cycle.

On HTTP error: parse `response.json().detail` for the error message, fall back to `HTTP {status}`. Display via `showToast(message, "error")`.

On 409 (duplicate setup): the API returns `{ "detail": "Setup already pending for {hostname}" }`. Display via error toast.

### Auto-Refresh

Existing `setInterval(refreshDashboard, POLL_INTERVAL_MS)` unchanged. QUADS status fetch added to the `Promise.all` array.

### Dropdown Menu (Secondary Actions)

For nodes with 2+ actions (D-08):

- Primary action: standalone button (first item in `actions` array).
- Caret button: adjacent to primary, contains character. On click, toggles a `.action-menu` div.
- Menu items: same button styling as inline action buttons, stacked vertically.
- Dismiss: click outside (document-level click listener that checks `contains()`), or click on a menu action.
- Position: absolute, anchored below the caret button, right-aligned to avoid table overflow.

```css
.action-group {
  display: inline-flex;
  gap: 0;
  position: relative;
}
.action-caret {
  padding: 0.3rem 0.4rem;
  border-left: none;
  border-radius: 0 0.375rem 0.375rem 0;
  /* inherits color from primary button variant */
}
/* primary button in group loses right border-radius */
.action-group > button:first-child {
  border-radius: 0.375rem 0 0 0.375rem;
}
.action-menu {
  display: none;
  position: absolute;
  top: 100%;
  right: 0;
  margin-top: 0.25rem;
  background: var(--accent-bg);
  border: 1px solid var(--border);
  border-radius: 0.375rem;
  padding: 0.25rem;
  z-index: 10;
  min-width: 8rem;
}
.action-menu.open { display: flex; flex-direction: column; gap: 0.25rem; }
.action-menu button {
  width: 100%;
  text-align: left;
  border: none;
  padding: 0.4rem 0.6rem;
  background: transparent;
  border-radius: 0.25rem;
}
.action-menu button:hover { background: rgba(51, 65, 85, 0.5); }
```
